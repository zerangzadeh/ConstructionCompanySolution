# BONIRA UI and UX acceptance checklist

Use CV-UI-01 for the systematic sweep. Apply the same applicable checks to the business and platform journeys. Record viewport, browser build, role, tenant/project/site, route, fixture, actual result and evidence for each item. Use 100% zoom at 1440 × 900, 1024 × 768 and 390 × 844 CSS px. Run one normal and one restricted role variant and test populated, empty and invalid states where applicable. A genuinely inapplicable check gets a reason at the check level.

| ID | Objective acceptance criterion | Evidence or method |
|---|---|---|
| UI-01 | Persian-first copy, document lang/dir and reading order are correct. Approved typography loads, Persian digits and Jalali display follow policy, and mixed phone, email, model-free business references and numbers keep their intended order. | DOM lang/dir, computed font, mixed-direction screenshot and one Jalali input-to-stored-date comparison. |
| UI-02 | At all three widths, documentElement.scrollWidth ≤ clientWidth (allow 1 CSS px rounding). No clipped action, title, field or dialog. Long tables may scroll in their own container with reachable controls. | Console measurement, screenshot and keyboard/scroll proof per viewport. Include long Persian and mixed-script values. |
| UI-03 | Home, desktop sidebar and mobile drawer offer the same entitled destinations. Active group/route, empty menu and role-specific visibility are understandable. Hidden module or foreign record is absent from shared links. | Menu and search comparison for entitled, restricted and platform-only roles. |
| UI-04 | The primary action is discoverable; consistent icon, label and semantics. Secondary and destructive actions remain distinguishable. Confirmation states the actual target and effect. Cancel restores focus and changes nothing. | Open with keyboard, cancel, reopen and confirm on sacrificial fixture. Compare state and focus. |
| UI-05 | Every editable input has an accessible label, unit and required state where appropriate. Invalid values produce localized field and summary errors, preserve valid input and focus/scroll to the error. | Submit invalid numeric/date/required values; record DOM and screenshots. File input reselection follows browser rules. |
| UI-06 | Filters, query, sort and pagination preserve intended context. Reset returns defaults; first/last/empty pages are usable. Search/select supports keyboard, dependent options, clear, Persian/Arabic numeral inputs where normalization is specified and additional pages. | Seed >1 page, test same-label foreign objects, reset and query retention. Compare visible results with authorized source IDs. |
| UI-07 | Loading or pending requests give feedback where asynchronous. Empty, filtered-empty, denied, missing, and failed actions give safe, understandable guidance and usable recovery. | Throttle a selector, submit validation error, use absent ID and restrict permission. Capture error state and network response. |
| UI-08 | Breadcrumb, contextual back/cancel and tab activation preserve legitimate project/site/filter context. Forged return URLs fail closed. Browser back and deep link behave consistently. | Follow both normal and contextual entry, then cancel and submit. Verify resulting URL and selected context. |
| UI-09 | Table headings, values, units and row actions remain associated at all widths. Long text, Persian digits, numbers and statuses remain readable and selectable. | Populate long values and zero/negative/decimal cases, inspect headers, focus and scrolling. |
| UI-10 | Status text, badge and outcome agree with the saved record and workflow. Success and failure feedback are distinct, and duplicate submission is prevented or safely rejected. | State witness and UI capture before/after each operation, including replay and confirmation. |
| UI-11 | Keyboard reaches intended elements in order. Focus is visible, mobile drawer/picker/dialog opens and closes by keyboard, Esc dismisses where supported and focus returns to trigger. Controls have meaningful accessible names; no color-only meaning. | Tab/Shift+Tab/Enter/Esc trace, accessibility-tree spot checks, and contrast checks using rendered colors. |
| UI-12 | Customer-facing labels, error pages, selector results and output cells use business terms. Raw UUIDs, stack traces, internal codes, object representations, storage URLs and secrets stay out of visible content. Approved business IDs and identifiers in necessary URL paths are evaluated in their designated contexts. | Safe HTML text, console and response check. For protected selectors and downloads also test direct URL and response headers. |
| UI-13 | Excel and print actions are discoverable and retain context; download/preview shows correct scoped data. Print omits chrome, controls and private metadata and remains legible when paginated. | Actual XLSX, print preview/PDF and source comparison through UAT-10. |

## Product Owner review

Objective failures become defects even when styling is otherwise acceptable. PO review covers Persian vocabulary within approved business meaning, visual hierarchy and density, preferred action prominence and overall comprehension. Use `NEEDS_PO_REVIEW` for a discretionary question with a named decision owner and side-by-side evidence. Keep the underlying technical result and the explicit PO decision in separate fields. Preserve the prior Contracts List decision dated 2026-11-01. Review other surfaces on their own evidence.
