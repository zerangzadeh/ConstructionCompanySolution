## Root Cause Addressed

`FORM_QUERYSET_NOT_SCOPE_FILTERED`,
`BUSINESS_PERMISSION_CHECK_WITHOUT_OBJECT_SCOPE`, and
`SHARED_FORM_HELPER_BYPASSED`: capability gates previously allowed entry while
organization-only form querysets disclosed ungranted same-tenant metadata.
`CASCADE_ENDPOINT_AUTHORIZATION_MISSING`: Workforce's site cascade previously
checked tenant/parent relationships without narrowing by effective object grants.

## Implementation

Each affected HTTP create view explicitly supplies membership resolved through
`get_active_membership(user=request.user, organization=request.organization)`.
Each form leaves its protected class-level `.none()` querysets empty when
membership is missing, invalid, or belongs to another organization. Canonical
`scope_queryset()` also rejects inactive membership/user/tenant and intersects
tenant identity with currently effective grants. No organization-only fallback
populates project-related choices.

Daily Report project, site, and phase choices and Equipment Assignment project
and site choices use the canonical scope mechanisms, preserving original
lifecycle filters and parent validation. PO project and approved request choices
use project-authority filtering without deriving parent authority from a site
grant. Workforce projects use the shared scoped project helper; bound sites
intersect selected authorized parent and site grants. Missing/malformed or
unauthorized parent resolves to no sites. Its HTTP cascade uses the same rules.

The same constructors handle initial GET, bound POST, and invalid redisplay.
All existing service authorization and transaction boundaries remain intact.
PO creation with an approved request uses the same protected create form/route.

## Authorization Semantics

AUTHORIZATION_SEMANTICS_CHANGED: NO

The patch restricts metadata to existing grants and preserves mutation authority.
Daily Report and Equipment services retain site-specific authorization, including
their existing site-parent handling. PO still requires project authority; a
site-only grant exposes neither its project nor its request choices for PO.
The shared context selector may still display the granted site's parent under
its existing context rules; PO's own project/request fields remain empty for
site-only authority.
Workforce's existing assignment service requires organization scope even when
the page's capability gate permits a project-scoped member. That restriction is
preserved: scoped A/B form submissions reach the existing service denial, while
an explicit organization grant retains the existing success path. No authority
is inferred from UI visibility or routing data.

## Same-Tenant Isolation

The isolated nonstaff, nonsuperuser Project Manager fixture has explicit A/B
project grants and no C/D grants. Tests examine protected querysets and rendered
HTTP bodies for UUID, label, code, title, request number, and contract number
disclosure, including invalid redisplay. Revoked, expired, future and absent
grants, inactive membership/user/tenant, and revoked roles are covered.

## Cross-Tenant Isolation

Tenant B's Project X and representative children are excluded from every
affected form and cascade response. Manipulated X submissions and direct service
calls must fail without creating business objects. A wrong-tenant membership
explicitly passed to a form produces empty protected choices.

## Manipulated POST

C/D/X project submissions are rejected by model choice validation. Mixed A/B
parent-child combinations are rejected, and site-only access excludes sibling
sites/phases. Tests compare business-object counts before and after rejected
requests and directly exercise unchanged service authorization.

## Invalid Redisplay

Missing-field and manipulated-choice requests reconstruct the same scoped
querysets. Response-body assertions check that unauthorized labels and UUIDs do
not reappear. Authorized B remains selectable on bound forms.

## Known-Good Controls

Expense and Estimate form/HTTP scope controls, shared context options, global
Project search, direct Project read denial, and unauthorized mutation services
are regression controls only; their implementations remain unchanged.
The new explicit A/B-scoped Expense/Estimate GET, bound form, invalid POST, and
context-option controls all pass. Their 31 older suite methods fail while
creating ungranted fixture Projects, identically on frozen source; those methods
do not establish a create-view regression. Direct-read denial permits only the
caller-supplied Project UUID in navigation `next`; fetched forbidden labels and
child identifiers must remain absent.
